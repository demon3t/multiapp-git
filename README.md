# mGit

mGit — приложение для Windows 10/11, которое хранит версии конфигурации Apache Superset в обычном Git-репозитории. В снимок входят дашборды, графики, датасеты с колонками и метриками, определения подключений и сохранённые SQL-запросы.

## Установка

1. Установите Git for Windows с Git Credential Manager. Путь к Git должен быть доступен в PATH.
2. Запустите release/mGit-Setup-0.3.1.exe. Сборка x64 без подписи.
3. Для коммитов настройте Git user.name и user.email в локальном репозитории или глобальном профиле.

## Экспорт и импорт

1. Подготовьте локальный Git-репозиторий. Клонировать HTTPS-репозиторий можно в разделе **Репозитории**. Git использует собственный credential helper. При пустом репозитории mGit может записать снимок в текущую начальную ветку.
2. В разделе **Приложения** нажмите **Добавить приложение**, выберите тип **Apache Superset** и папку Git, затем укажите URL и данные для входа. Приложение появится во вкладках. Если вы обновились со старой версии, откройте сохранённое подключение через **Изменить** и укажите папку Git.
3. Нажмите **Проверить** в списке приложений. mGit покажет версию, наличие роли Admin и доступность API. Для полных снимков нужна роль Admin. Корпоративный CA в формате PEM можно добавить при редактировании в **Дополнительных параметрах Superset**. Пароли, токены и строки подключений шифруются Windows DPAPI.
4. Откройте вкладку источника и раздел **Экспорт**. Снимок будет подготовлен для текущей ветки привязанного Git-репозитория. Укажите каталог, например snapshots/superset/assets. Для выборочного экспорта загрузите список и отметьте нужные объекты. mGit добавит зависимости по UUID.
5. Нажмите **Подготовить экспорт**, проверьте состав и YAML до и после. Затем отдельно нажмите **Записать снимок** и **Создать коммит**. Push запускается с экрана репозитория. Выборочный экспорт заменяет содержимое указанного снимка, а план показывает исключённые файлы.
6. Добавьте приложение для целевого Superset и привяжите репозиторий, содержащий нужный коммит. В дополнительных параметрах цели добавьте для каждого определения подключения строку вида «UUID пробел SQLAlchemy URI». UUID доступен в YAML. При смене URL mGit требует заново задать пароль и подключения.
7. Откройте вкладку цели и раздел **Импорт**. Выберите ветку, тег или SHA. Изучите план, затем подтвердите импорт названием приложения и полным SHA. Резервный экспорт сохраняет проверенную копию метаданных с нейтральными URI. Для восстановления нужны целевые подключения.
8. После импорта mGit сверяет UUID и связи штатным экспортом цели. Если сервер не подтвердил запрос, приложение показывает то, что удалось проверить, и оставляет файл блокировки. Перед снятием такой блокировки найдите указанный файл, проверьте журнал Superset и убедитесь, что сервер завершил предыдущий импорт. Для повторной проверки есть отдельное действие на экране **Импорт**.

В режиме **Только метаданные** доступны проверка файлов выбранного Git-коммита и сводка состава. Этот режим не подключается к стенду и не запускает импорт.

Опция **Частичный снимок** позволяет проверить или подготовить к импорту совместимые объекты. Отчёт показывает исключённые файлы и причины, включая зависимости от исключённых объектов. По умолчанию для полного импорта по-прежнему требуется успешная проверка всего снимка. Снимки с очищенным URI `REDACTED` используют подключения, заданные для целевого стенда. Число YAML-файлов не ограничено, для содержимого снимка действует лимит 64 МиБ.

## Сборка и запуск из исходников

Требуются Node.js 24 и Git. В PowerShell из корня проекта выполните:

    npm ci
    npm start
    npm test
    npm run dist

Установщик появится в release. Распакованная сборка находится в release/win-unpacked. Исходники ядра находятся в src/core, Electron в src/main.ts и src/preload.ts, интерфейс в src/ui.tsx, CLI в src/cli.ts.

## CLI

После npm run build вызовите node dist/cli.js --help. Команды validate, export, plan, import и verify принимают --repo, --folder и полный --commit. Для export этот SHA должен совпасть с HEAD. По умолчанию export возвращает сводку, ключ --write записывает просмотренный снимок. Команда import выполняет новую предварительную проверку и требует --apply. Для целевых операций укажите --target и --environment. Для PROD укажите также --name и --confirm с названием и SHA через пробел. --ca принимает путь к PEM. --backup указывает новый путь для ZIP перед импортом.

Пример локальной проверки:

    node dist/cli.js validate --repo D:\repos\metadata --folder snapshots/test/assets --commit <полный-SHA>

Передавайте секреты через переменные среды CI или защищённые переменные процесса. Для доступа используйте MGIT_TOKEN или MGIT_USERNAME и MGIT_PASSWORD. Для импорта задайте MGIT_CONNECTIONS_JSON с отображением UUID на SQLAlchemy URI. CLI возвращает JSON. Коды выхода: 0 — успех, 1 — операционная ошибка, 2 — параметры, 3 — ошибки валидации или проверки результата, 4 — сервер не подтвердил применение.

## Проверки

Модульные тесты проверяют YAML и зависимости, фильтрацию секретов, работу с локальным Git, сетевой таймаут и истечение авторизации. После сборки установщика команда node --test tests/desktop.cjs проверяет запуск упакованного приложения и защищённое сохранение профиля. Интеграционный тест запускается против отдельных локальных Superset 6.1.0 c синтетическими метаданными и выделенным PostgreSQL без опубликованного порта. Для воспроизведения выполните в двух терминалах:

    docker compose -p mgit-integration -f tests/superset/compose.yml up
    npm run test:integration

Вторую команду запускайте после готовности обоих API на портах 18088 и 18089. Тест проверяет штатный экспорт всех пяти типов, запись и коммит через Git, неизменный повторный экспорт, резервный экспорт, импорт из SHA, проверку связей и отсутствие дублей после повторного импорта. Все учётные данные из тестовых файлов относятся к локальным контейнерам.

## Обновления

В верхней строке окна откройте **Обновления → Проверить сейчас**. mGit сравнит текущую версию с последним опубликованным стабильным релизом в GitHub Releases. Автоматическая проверка включается в этом же меню. После запуска приложения она выполняется через 15 секунд, затем раз в сутки, пока приложение открыто.

Для закрытого репозитория сохраните GitHub-токен с правом Contents: Read для demon3t/multiapp-git. Токен шифруется Windows DPAPI и используется для запросов к API GitHub. При наличии новой версии откройте **Релизы на GitHub** и скачайте установщик через браузер.

## Ограничения 0.3.1

- Сквозной сценарий рассчитан на Superset 6.1.0 и ZIP assets 1.0.0. Другие версии Superset, корпоративный CA и реальный Azure DevOps/TFS требуют проверки в соответствующих окружениях. HTTPS-адрес Azure DevOps/TFS передаётся Git без преобразования пути.
- Вход поддерживает локальную учётную запись Superset и bearer access token. Интерактивный SSO, автоматическое обновление внешнего токена, SSH-туннели и секретные параметры драйверов пока не поддерживаются.
- Интеграция ограничена пятью заявленными типами. Темы, отдельные файлы данных, дополнительные типы объектов и нераспознанные файлы блокируются. Проверка формата локальная, окончательную проверку схемы даёт API Superset.
- URI в YAML заменяется нейтральным значением mGit. Проверка секретов эвристическая. Просматривайте diff перед коммитом, особенно поля, где можно хранить произвольный текст или SQL.
- Штатный импорт Superset может обращаться к целевым аналитическим подключениям и обновляет объекты по UUID. Тестирование подтверждает UUID, типы и связи, а не полное совпадение всех сериализованных полей. Удаление объектов на цели и автоматический откат отсутствуют. Блокировка защищает запуск из mGit и CLI в пределах временного каталога одного пользователя, параллельные изменения из других клиентов контролирует сервер.
- Git-интерфейс поддерживает работу с выбранной веткой, fetch, push в origin и коммит просмотренного снимка. Разрешение конфликтов, merge и создание PR выполняются внешними средствами.
